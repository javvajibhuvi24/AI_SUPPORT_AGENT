## Written Reflection

**Design Decision**
I chose to integrate the Gateway tools by invoking \load_tools()\ directly before the agent is instantiated, rather than wrapping the process in an \sync with\ context block that was previously problematic due to SDK version differences. By simply loading the tools and appending them to the agent's tool list, we maintain a clean and reliable setup for the agent alongside its memory hooks, RAG knowledge base, and live browsing capabilities. This integration pattern enables seamless hybrid execution: the agent locally runs Code Interpreter sandboxes and Bedrock Knowledge Base queries, while simultaneously delegating Lambda-backed tasks (like order tracking) through the API Gateway MCP client.

**Challenge Encountered**
A significant challenge during implementation was the context manager behavior of the Strands \MCPClient\. Initially, wrapping the client in an \sync with\ block resulted in a \TypeError\ because the object didn't natively support asynchronous context protocols in this environment. Attempting to use a standard \with\ block then triggered an \MCPClientInitializationError\ when \load_tools()\ was called, as both the context manager's \__enter__\ and the tool loader attempted to start the client session simultaneously. I resolved this by removing the context manager wrapper entirely. Calling \wait gateway_client.load_tools()\ directly allowed the client to manage its own startup sequence gracefully, successfully bridging the MCP server and returning the required tools.

**Production Consideration**
For a real-world production deployment, security around the AgentCore Gateway must be hardened. The API Gateway proxy connected via the Bedrock Gateway is currently using the \NONE\ authorizer, which leaves the backend customer and order lookup operations exposed without authentication. Before releasing this agent to live customers, it is crucial to implement proper access controls—such as JWT validation, OAuth, or AWS SigV4. This ensures that incoming MCP requests genuinely originate from the trusted AgentCore runtime, preventing unauthorized access, and guarantees that customers can only query order and refund data explicitly associated with their authenticated session IDs.
